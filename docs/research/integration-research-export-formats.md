## 11. Export file formats (Sage 50, TallyPrime, DATEV)

The owner decided these three use **export files written inside WordPress**, with no helper program (see the connection methods spec). This section records what each system's import accepts. DATEV's developer pages are single-page apps that could not be read, and no official Sage 50 UK import-layout page was found, so those parts are third-party.

### 11.1 TallyPrime (best documented)
- **Import route** (D): press Alt+O, choose Transactions, type the file path, choose whether to back up, press Enter. XML works in all releases; JSON from release 7.0; Excel from 4.0. The target company must have the same F11 features enabled as the source. Tally's Excel mapping templates include Shopify but none for WooCommerce.
- **XML envelope** (D): `ENVELOPE > HEADER (VERSION 1, TALLYREQUEST Import, TYPE Data, ID Vouchers) > BODY > DESC > DATA > TALLYMESSAGE > VOUCHER`. Voucher attributes `VCHTYPE="Sales" ACTION="Create"`. Invoice-mode tags: `DATE` (yyyymmdd), `VOUCHERTYPENAME`, `VOUCHERNUMBER`, `PERSISTEDVIEW "Invoice Voucher View"`, `ISINVOICE Yes`; the party `LEDGERENTRIES.LIST` with `ISDEEMEDPOSITIVE Yes`, `ISPARTYLEDGER Yes` and a `BILLALLOCATIONS.LIST`; further `LEDGERENTRIES.LIST` blocks for freight and tax; one `ALLINVENTORYENTRIES.LIST` per stock item (`STOCKITEMNAME`, `RATE`, `AMOUNT`, `ACTUALQTY`, `BILLEDQTY`) with `ACCOUNTINGALLOCATIONS.LIST` for the sales ledger.
- **Balancing** (D): debit and credit totals must be equal and Tally does not round for you, so the file needs an explicit round-off ledger line.
- **JSON**: JSONEx is recommended for new work (needs `svVchImportFormat` and `svCurrentCompany`), but the voucher JSON payload sits in a linked Word file that could not be read. **Write XML** because every release reads it.
- **Refund**: a Credit Note voucher with the signs reversed (I); no official Credit Note sample was found.
- **Duplicates** (D): a setting "Overwrite voucher when a voucher with same GUID exists" (Alt+O, Configuration); with No, re-importing creates duplicates; voucher IDs are `REMOTEID` and third-party XML must supply a unique one; Tally's wording is to import the file only once. The REMOTEID tag syntax was not read. The plugin emits a stable per-order ID (I) and keeps an export log.
- **Traps** (D): a "DESC not found" error means a referenced master is missing, so ledgers and stock items must exist first; use current AED and SAR currency and entity codes (for example `&#8387` for AED) because legacy codes can break the import; errors go to `Tally.imp` and the Exceptions report. UAE VAT-specific voucher tags and the XML encoding: not found.

### 11.2 Sage 50 UK (weakest sourcing, all third-party)
- **Route** (3P): File, Import, "Audit Trail Transactions". Sample templates are in `C:\Program Files (x86)\Sage\Accounts\Import Templates`, including "Audit Trail Transaction FULL". The core import posts only to the Audit Trail and cannot create Invoicing or Sales Order module documents. One user only while importing; back up first.
- **Columns, in order** (3P): Type, Account Reference, Nominal A/C, Department, Date, Reference, Details, Net, Tax Code, Tax, Exchange Rate, Ex.Ref, User Name. Required in a working integration: Type, Account, Nominal, Net, Exchange Rate (use 1). Net up to 8+2 digits; tax code T0 to T99 (default T0); date formats ddmmyy, ddmmyyyy, dd/mm/yy, dd/mm/yyyy. Types: SI sales invoice, SC sales credit, SA, SR, SP receipts and refund payments. Versions 7 to 11 have no Exchange Rate column; from version 12 the Exchange Rate and User Name columns exist; from version 17 field mapping makes column order irrelevant.
- **Grouping**: "Audit Trail Transactions Grouped" merges lines with the same type, account, date, non-blank reference and exchange rate into one transaction; the plain import makes one header per line.
- **Mapping (I)**: SI lines with account, sales nominal, date, order number as Reference, net, tax code, tax and rate 1; shipping and fees on their own nominal lines; refunds as SC lines. Use one "WEB" customer account to avoid account-reference failures. Always write the Tax field explicitly (sources conflict on whether blank means calculated or 0.00).
- **Duplicates**: no duplicate check found; Sage 50 is lax about duplicate references (3P). The plugin carries the warning.
- **Traps** (3P): account references and nominal codes must already exist; regional date format must match. A "0.5 MB file" limit appears on one page only.

### 11.3 Sage 50 US and Canada
- **Route** (3P for the menu path): File, Select Import/Export. Journals supported include General, Sales, Sales Order and Cash Receipts; import adds new transactions only and cannot edit existing ones (D). Import lists first (Chart of Accounts, Customers, Inventory Items), then journals (D).
- **Rules** (D): the same fields are required as for manual entry; a Transaction Number is required and every distribution line of one transaction shares it; at most 160 distributions per transaction (154 for AR journals); dates beyond the end of the second open fiscal year are rejected; avoid double quotes in text.
- **Fields** (3P, low confidence): header Customer ID, Invoice/Ref No, Date, Terms, AR Account, Freight, Sales Tax; line Item ID, Description, Qty, Unit Price, Amount, Sales GL Account, Taxable; dates MM/DD/YYYY. No official Sales Journal field list was found.
- **Duplicates** (D): a duplicate invoice number for the same customer ID is not allowed, so use the order number as the invoice number.

### 11.4 DATEV
- **Official specification** (D, DATEV document 1003221, an older ASCII description): semicolon delimiter, text in double quotes with embedded quotes doubled, decimal comma, no thousands separator, heading row, no trailing delimiter, character set "ANSI". Belegdatum is `TTMM`, other dates `TTMMJJJJ`. Fields: 1 Umsatz (positive, 10+2), 2 Soll/Haben-Kz (S or H), 3 WKZ, 7 Konto (up to 9 digits), 8 Gegenkonto, 9 BU-Schluessel (4), 10 Belegdatum, 11 Belegfeld 1 (up to 36), 12 Belegfeld 2, 14 Buchungstext (60). Belegfeld 1 allows digits, letters and `$ & % * + - /` and not spaces, umlauts or `. , ; :`; it is the key for open items. Fill it always. Keep each file inside one fiscal year (Belegdatum within the current year). The BU key list is DATEV document 0907054.
- **Header** (3P): row 1 `"EXTF";700;21;"Buchungsstapel";<format version>;` then the timestamp `YYYYMMDDHHMMSSFFF`, Berater (1001 to 9999999), Mandant (1 to 99999), WJ-Beginn `YYYYMMDD`, Sachkontenlaenge, date from and to, description (30), dictation code (2), booking type 1, Festschreibung 0 or 1, WKZ; row 2 holds the column names.
- **Format version and column count: unresolved.** Third parties say format version 13 with 125 columns (one also offers version 12 with 121); the DATEV PDF numbers up to field 125; the commonly remembered figure of 116 columns matches an older version. Every row must match the column count declared in the header.
- **Encoding**: the official text says "ANSI"; third-party plugins write Windows-1252 and say UTF-8 with BOM is accepted by current releases (unverified). Write Windows-1252.
- **Mapping (3P, I)**: one posting per VAT rate, Konto = debtor, Gegenkonto = revenue account, S for a sale, gross positive Umsatz, `TTMM` Belegdatum, Belegfeld 1 = order number, BU key empty for automatic-tax accounts, Festschreibung 0; a refund uses the same accounts with H, dated on the refund. Foreign-currency orders are not covered. Accounts must match the client's chart of accounts and account length.
- **How the adviser imports it** (D, DATEV document 9211450, 22 Jan 2025): in Rechnungswesen, Bestand, Importieren, Stapelverarbeitung, Importieren. **Saving the file in Excel breaks the header** and DATEV no longer recognises it. Fallback: ASCII import (Bestand, Importieren, ASCII-Daten) with "Import ab Zeile" set to 2. "DATEV-Format aendern" lets the adviser correct Berater number, Mandant number, year and batch date. The Unternehmen online import path was not found.
- **Duplicates**: no dedupe rule found; the adviser can append to a batch or create a separate one. The plugin keeps its own export log and warns on re-download.
- **Rechnungsdatenservice** (D): built on DATEV's XML interface online; sends invoice data to Unternehmen online as booking proposals; needs partner onboarding and access rights, so it is not viable for a free plugin. The XML schema: not found.

### 11.5 What this means for the export design
- Keep a per-order export log in every format; fail early on a missing ledger or code mapping; write an explicit round-off line (Tally).
- Per-system settings: Tally (company name, ledger names); DATEV (consultant and client numbers, financial year start, account length, debtor and revenue accounts, tax keys); Sage 50 UK (web customer account, nominal codes, tax codes); Sage 50 US (customer IDs that exist first, sales and freight accounts).
- Tell the merchant never to open or save a DATEV file in Excel.
- The DATEV column count and the Sage 50 UK layout must be confirmed against a real import before release; test files from each vendor's own sample data are the proof.
