# Core services

Reference for the modules built on top of `includes/Core`. Keys are constants of `Estasoft\SyncEngine\Core\Services`; every service is also registered under its class name, so `$container->get( QueueRepository::class )` and `$container->get( Services::QUEUE_REPOSITORY )` return the same object. Namespace for everything below: `Estasoft\SyncEngine\Core\...`. Detail lives in the class docblocks.

The Mapping module sets `Services::PAYLOAD_BUILDER` (`'payload_builder'`) to a `Sync\PayloadBuilderInterface`. The queue resolves it lazily; when it is missing an item fails with `SYNC-CFG-001` and nothing is sent.

## Database

Nine tables named `{prefix}estasoft_sync_{connections,queue,logs,mappings,id_map,state,idempotency,recon_runs,recon_diffs}` (utf8mb4, created with `dbDelta`). `Schema::VERSION` (now `1.1.0`) is stored in the autoloaded option `estasoft_sync_db_version`; `Migrator::maybeMigrate()` runs on `plugins_loaded` (21) and `admin_init` (1) and is idempotent. All other options are not autoloaded. Time is UTC `Y-m-d H:i:s`; the repositories return ISO `...Z` strings in the shapes of `src/api/types.ts`. Log timestamps keep milliseconds: stored as `datetime(3)` and returned as `2026-11-02T12:00:00.250Z` (still ISO 8601; `Time::isoMs()`). Other timestamps stay whole seconds.

Schema 1.1.0 (spec 5.2 / 5.3): queue `priority tinyint default 5` (0 to 9, lower first) in the claim index `(state, next_attempt_at, priority)`; queue `reaps` (times the stale lock reaper took the item back); `UNIQUE (connection_id, idempotency_key)` on the queue; `error_message varchar(500)`; logs `ts datetime(3)` and `message varchar(500)`; connections `disconnected_at`. `dbDelta` cannot drop an index, change one or add a unique index over duplicate rows, so `Database\Upgrades` runs first and is safe to run again: it cuts long messages to 500 characters, drops the old two-column `claim` and plain `idempotency` indexes, deletes rows that repeat a key on a connection (the lowest id stays), and rewrites `secret_hints_json` as presence flags. A fresh install skips it.

## Repositories

Only repositories touch `$wpdb`. Every query is prepared; table names come from `Tables`.

- **ConnectionRepository**: `find(id): ?Connection` (decrypted, for sending; throws `Crypto\CryptoException`), `findWithoutSecrets(id)`, `findPublic(id): ?array` (`Connection` of types.ts minus `credentials`; adds `secret_hints`, `secrets_readable`, `config`; `secret_hints` is `{"api_key": true}`, a presence flag per saved secret and never a character of it, so the TypeScript `Connection` type needs no change: it only reads `credentials[].has_value`), `all(): array` (public arrays), `allWithoutSecrets()`, `forConnector(id)`, `activeIds()`, `pausesDue()`, `create(config, secrets, settings): int` (`config` carries `connector`, `type`, `label`, the rest is stored as config), `update(id, changes)` (keys `label`, `config`, `secrets` where `''` keeps and `null` removes, `settings`, `credential_expires_at`, `credential_warn_days`, `inbound_enabled`; when the saved secrets were written with another key, a save that does not give every saved secret again (or remove it with `null`) throws `CryptoException` with no code and writes nothing), `setStatus(id, ConnectionStatus, ?pausedUntil, ?reason)`, `incrementFailures`, `resetFailures`, `tripCircuit`, `scheduleProbe`, `resumeFromCircuit`, `recordSuccess(id, ms)`, `recordFailure(id, ms)`, `delete(id)` (disconnects: wipes secrets, stamps `disconnected_at`, keeps the row and its history; `setStatus` to anything but disconnected clears the stamp).
- **QueueRepository**: `enqueue(connectionId, type, entityId, event, partitionKey, key, mode = Live, maxAttempts = 5, display = [], priority = 5): int` (a repeated `(connection, key)` returns the existing item's id), `enqueueOnce(...)` (same arguments, returns `{id, created}`), `idByKey`, `claim(limit, lockSeconds, workerId, ?connectionId): Item[]` (`workerId` is the lock token; priority first, then age; an empty answer means nothing is waiting: a worker that loses a race for the rows it picked looks again, later and further down the list, up to 8 times), `markSynced`, `markRetrying`, `markFailed`, `release` (back to queued without a try), `extendLock`, `skip`, `restore`, `retry`, `failedIdsByGroup(code, ?cause, limit = 5000, afterId = 0)`, `find(id): ?Item`, `latestForEntity(EntityType, entityId): ?array` and `forEntity(EntityType, entityId, limit = 20): array` (every item of one WooCommerce object, newest id first, in the `QueueItem` shape of `query()` rows; an exact match on `entity_type` and `entity_id`, so it uses the `entity` index and does not lose items the way a text search does), `findRow(id): ?array` (`QueueItem` plus idempotency_key, partition_key, mapping_version, log_id), `siblings(id)`, `query(QueueQuery): Paged`, `countsByState(?connectionId, ?mode = 'live')`, `syncedToday`, `countSyncing`, `hourly()` (24 buckets), `oldestWaiting()`, `attentionGroups()`, `reapStale()` / `reapStaleLockIds()` / `reapStaleLocks()`, `prune()`, `pruneDisconnected(days = 30)`, `setDisplay`, `setLastLog`, `findUnfinished`, `noteChangedWhileWaiting`, `withClaimLock(Closure, waitSeconds = 2, fallback)`, `atomically(Closure)`, `clean(message, limit)`.
  - **Lock token.** `markSynced`, `markRetrying`, `markFailed`, `release` and `extendLock` take an optional last argument `?string $lockToken` and now return `bool`. With a token the write only happens while the row is still `syncing` and `locked_by` that token; `false` means the lock was lost and the caller must discard its result. Without a token they work as before (the Jobs module marks unclaimed rows this way). `retry` resets `attempt` to 0 for failed and for retrying items (QUE-11) and `reaps` to 0, and so does `restore`.
  - **Messages.** Every `error_message` written (and `error_cause`, cut to 191) is redacted first (`Redactor::message`: secrets always, personal data while the setting is on) and cut to 500 characters. Do not redact again before calling.
  - **Poison items.** The reaper counts how many times it took the same item back (`reaps`). The third time the item becomes `failed` with `SYNC-LOCK-001` and the cause "Worker stopped 3 times", so Needs attention shows it; a person's retry or restore starts the count again, and a worker that gets as far as writing a retry result clears it.
  - **Units.** `atomically(Closure $work)` runs writes as one unit that is kept or dropped whole: in a transaction of its own when the connection has none open, in a savepoint inside the caller's transaction when it has (never nested, never committed behind the caller's back). The work fails by returning `false` or by throwing (the exception is passed on after the rollback); anything else, `null` included, is success and is returned. A deadlock is tried once more, only in a transaction of its own.
  - **Claim lock.** `withClaimLock()` runs a closure while holding a MySQL named lock (`GET_LOCK`, released in `finally`). It returns the fallback if the lock is not free within the wait. The lock name is made from the database name and the queue table name (named locks are shared by the whole database server, so two sites with the same table prefix in two databases must not share one).
- **LogRepository**: `write(entry)` (message cut to 500 characters, time kept in milliseconds), `query(LogQuery): Paged`, `find(id)`, `latest(n)`, `timeline(queueId)`, `prune(days)`, `clear()`, `csv(LogQuery): string`.
- **MappingRepository**: `live`, `draft`, `find`, `versions`, `saveDraft`, `discardDraft`, `publish`, `rollback` (new live version copied from an old one, numbered highest + 1), `seedLive` (version 1), `replaceLive` (unversioned types such as `tax`). Publish and rollback run in a transaction that locks the connection and type. The history is strictly linear: version numbers only go up. If a rollback created a version after the draft was made, `publish` renumbers the draft to highest + 1 inside the same transaction (draft v4, rollback to v2 makes live v5, publish makes live v6 and retires v5), so the returned live version may have a different number than the draft had, and `mapping_version` on queue items only increases.
- **IdMapRepository**: `get`, `link` (a person's `is_override` link is never replaced by automatic matching), `forget`, `findBySku`, `findWcId`. Type is an `EntityType` or the string `product`.
- **StateRepository**: `get`, `isUnchanged(hash)`, `save`, `mergeExtra`, `forget`.
- **IdempotencyRepository**: `reserve`, `attach` (returns whether the ledger row changed), `release`, `queueIdFor`, `exists`, `markDone`, `get`, `nextOrdinal` (`COALESCE(MAX(ordinal), -1) + 1`; this is what the Enqueuer uses), `countFor` (a plain count, kept for old callers, never use it to build a key), `prune`.
- **ReconRepository**: `startRun`, `finishRun`, `addDiff`, `findRun`, `runs`, `lastRun`, `diffs`, `diff`, `markRepaired`, `ignore`, `openCount`, `prune`.

`QueueQuery::fromArray()` and `LogQuery::fromArray()` take request parameters named as in types.ts and drop anything not recognised. `LogQuery` filters: `level`, `search`, `connection_id`, `queue_id` (int), `code` (a SYNC code, exact match, cut to 20 characters) and `range` (`1h`, `24h`, `7d`, `30d` or `all`; default and fallback `all`; measured back from now), plus `page` and `per_page`. `LogRepository::csv()` applies the same filters as `query()`. `Paged::toArray()` is the `Paged<T>` shape.

## Queue

- **Enqueuer::enqueue(EntityType, entityId, event, ?connectionId, array $meta = []): ?int**. Never throws, no network, one row. `$meta` keys: `partition` (a refund passes `order:{parent id}`), `label`, `customer`, `total_minor`, `currency`, `search`, `priority` (0 to 9, default 5). Every event type can repeat (`created`, `paid`, `updated`, `refunded`, `cancelled`, `delivered`, and any a module adds): an event joins an item of the same kind that is still queued, retrying or failed; once that one is done the next event adds a new item with the next ordinal. The key is `sha256("v1:" . connection . ":" . type . ":" . id . ":" . event . ":" . ordinal)` and the ordinal is the highest stored ordinal plus one, not a count, so cleaning the ledger never reuses a key. Two requests racing for one key end with one item (the queue's unique index backs the ledger). The ledger key, the queue row and the link between them are written as one unit (`QueueRepository::atomically()`): a transaction of its own when none is open, a savepoint inside the order's transaction when one is, so a failed write leaves neither a key without an item nor an item without its key, it is safe to call inside an open transaction (QUE-1), and it still never throws. Shadow mode gives `mode = shadow`.
- **Shadow mode** (`OnboardingState`): once `shadow_started_at` is set it stays on until something explicit ends it: `endShadow( DateTimeImmutable $at, string $reason ): array` (stores `shadow_ended_at`, `shadow_end_reason` and `mode = live`), a `mode` of `live`, or the marker `answers.shadow_ended_by` that the Jobs `ShadowService` writes. The date in `shadow_ends_at` is information only: a date in the past, or one that cannot be read, does not end it. Starting a new window (a new `shadow_started_at`) clears the previous end. The state also carries the optional keys `shadow_ended_at`, `shadow_end_reason` and `mode`.
- **Worker::run(maxSeconds = 20, concurrency = 2): WorkerReport**. Never more than 20 seconds. Resumes ended pauses, probes open circuits and reaps dead locks first. Honours per-connection concurrency and requests per second, the global concurrency setting, pauses and the breaker. The `workerId` of a run (a UUID) is the lock token of every item it claims. Counting what is running and claiming what is left is one step under the claim lock (`Queue\ClaimPlanner`), so several workers on one database never go over the global or per-connection limit; if another worker holds the lock the run ends as idle.
- **Requests per second** is a limit on item starts per second (one slot from the limiter before each item), not on HTTP calls. An item can make several calls (look-up, send, read-back), so a connector that must keep to a hard limit of the other system paces its own calls.
- **ItemProcessor::process(Item, ?string $lockToken = null): Outcome**. Build payload, skip a no-op by hash, look the record up before the first send (SYNC-DUP-001), send, classify, write the result. The lock is refreshed (and checked) before each call to the connector. With a token every write to the row is guarded by it; if the lock was lost the result is thrown away, the row is left alone, a warning with `SYNC-LOCK-001` is logged, no hook fires and the outcome is `Outcome::LockLost` (counted as held in `WorkerReport`). What the other system now holds (id map, state hash, idempotency ledger) is still recorded, so the next worker does not send twice. Shadow items are built and looked up read-only but nothing is sent or stored in either system. A refused sign-in (AUTH-001) pauses the connection and leaves the item queued; AUTH-002/003/005 mark it needs-reconnect; a missing key (CFG-002) pauses it. The log excerpts use `PayloadResult::$sensitivePaths` (see below).
- **RetryPolicy**: 60 s, 300 s, 3600 s, 86400 s plus 0 to 20 s jitter, `Retry-After` wins when longer (cap 24 h), five tries. **CircuitBreaker**: threshold and probe interval per connection (`paused_until` holds the next probe time). **RateLimiter**: one slot per `1 / rate` seconds per connection, shared by all workers through the object cache or an options row. **Reaper**: locks last 60 s; it reports only the rows it really changed, and logs an error for a poison item.
- **QueueService** (REST façade): `retry`, `retryMany`, `retryGroup(code, ?cause)` (works through the whole group in batches of 500; `retryMany` and the other bulk forms take at most 500 ids), `skip(id, reason)`, `skipMany`, `restore`, `restoreMany`, `bulk(ids, action, ?reason)`, `syncNow()`, `detail(id)` (`QueueItemDetail`). After each item a person changes with retry, skip or restore (also in the bulk forms), the action `estasoft_sync_item_state_changed( Item $item )` fires once, with the item as it is after the change.
- **PauseController**: `pause(id, ?minutes)`, `resume(id)`, `pauseAll`, `resumeAll`, `resumeDue`, `holdForPerson(id, code, status, system = '', message = null, reason = null)`. The real reason of a pause is stored in `paused_reason` and returned by `ConnectionRepository::findPublic()` / `all()` as `paused_reason`: `person` (paused by hand), `circuit` (the breaker), `sign_in` (a refused, expired or unfinished sign-in: AUTH-001, 002, 003, 005, and a key that no longer opens the saved credentials) or `key_missing` (no usable `ESTASOFT_SYNC_KEY`: CFG-002), or null when not paused. The same value is the second argument of `estasoft_sync_connection_paused`. `holdForPerson` takes it from the code unless a caller names it. The TypeScript type of `Connection.paused_reason` has to be widened to `'circuit' | 'person' | 'sign_in' | 'key_missing' | null`.
- **Scheduler** (static `schedule()`, `unschedule()`, `ensureScheduled()`, `cronRunsOnVisits()`, `usesActionScheduler()`): five recurring tasks in the group `estasoft-sync`: `estasoft_sync_run_queue`, `_reap_locks`, `_probe_connections` every minute, `_prune_data`, `_purge_actions` daily; WP-Cron when Action Scheduler is missing. `lastRunAt()` for the readiness check. The purge deletes finished Action Scheduler rows of the group older than 7 days (PRF-6, `Scheduler::PURGE_AFTER_DAYS`) in batches. The prune task (`RetentionJob::run()` returns `{queue, disconnected, logs, idempotency, recon}`) also deletes the queued and retrying items of a connection 30 days after it was disconnected (CON-9); the connection, its mapping versions and the id map stay.
- **ErrorClassifier**: `classify`, `fromResponse(HttpResponse, system): ?ConnectorError` (default HTTP mapping: 2xx is success; 3xx is VAL-002 "the address redirects, use the final address" and needs a person; 401 AUTH-001, 403 AUTH-004, 429 RATE-001, 408/425/transport NET-001, certificate NET-003, 5xx NET-002, other 4xx VAL-002), `cause`. `classify` returns a copy of the error whose `reason`, `field`, `message`, `error` and `detail` text is redacted and cut to 300 characters, so no message, log entry, hook or email carries the other system's raw text.

## Settings, capabilities, logging, crypto

- **Settings**: `get()` is the `Settings` of types.ts; `update(changes)` throws `Support\ValidationException` with one message per field (`errors()`); `validate(changes)` only reports. Getters for each field. Ranges are in `Support\Ranges` (also `SAFETY_BUFFER` for the stock job). **ConnectionSettings** does the same for the reliability settings of a connection, and `defaults($connector->rateLimitHints())` gives the starting values.
- **Capabilities**: `MANAGE`, `CONFIGURE`; static `grant()`, `revoke()`, `userCanManage()` (true for configure too), `userCanConfigure()`.
- **Logger** `info|warning|error(message, context)` returns the entry id or null and never throws. Context: `connection_id`, `queue_id`, `entity_ref`, `code`, `http_status`, `duration_ms`, `attempt`, `mapping_version`, `request`, `response`, `sensitive_paths`. Messages and excerpts are redacted first (`Redactor::namesFromSourcePaths()` turns mapping source paths into field names; `sensitive_paths` are paths such as `partner.vat` and match fields whose names, ending in those segments, lead to them; the queue passes `PayloadResult::$sensitivePaths`); secrets are removed even when personal-data redaction is off, including `user:password@host` in addresses; excerpts are cut to the 2 KB / 8 KB / none setting and a payload over `payload_cap_bytes` is replaced by a note.
- **Redactor**: `message(text, personal)`, `secrets(text)`, `personal(text, barePhones = true)`, `structure(data, personal, sensitivePaths)`, `excerpt(...)`. Phone numbers are found with a plus, `00` or a leading zero, and also as a bare run of 9 to 15 digits with separators (`971501234567`, `(212) 555-0199`) unless it looks like money (a decimal tail or a currency next to it), a date, an IP address, an id or total named by the words before it (order, invoice, sku, id, total ...), or a JSON number; short numbers, codes with letters (`IT00123456`) and `"tax":123456` are left alone. More personal field names are removed (`name`, `recipient`, `iban`, `date_of_birth`, ...).
- **SecretBox** (`ESTASOFT_SYNC_KEY`): `keyAvailable()`, `keyTooShort()`, `fingerprint()`, `encrypt(array)`, `decrypt(string)`, `generateKeyLine()`. The key must be at least 32 characters (`SecretBox::MIN_KEY_LENGTH`); a missing key or a shorter one throws `CryptoException` with `ErrorCode::Cfg002` (the short one says it is too short); a changed key throws one with no code. The cipher key is `sodium_crypto_generichash` of a context string and the key material, stored text starts with `v2.`. There is no work-factor KDF on purpose: the constant is a random value generated by the plugin (256 bits), not a password a person chose, so stretching it adds nothing; the length minimum is the guard. Text from the first development builds (`v1.`) can still be read.
- **Support**: `Money` (minor units, exponent table), `Time`, `Uuid`, `Json::canonical()`, `DayRange`, `WpHttpClient` (30 s, TLS verified, unsafe URLs refused, no redirects).

## Lifecycle

`Installer::activate(networkWide)`, `deactivate()`, `uninstall()` (loops over sites on multisite; erases data only when `delete_on_uninstall` is on), `installSite()`. `DataEraser::erase(revokeCapabilities, ?deleteUserMeta = null)` is also what the Delete data tool should call. It deletes only the options named in `OptionNames` (Core's, the other modules' as of this version, and the filter `estasoft_sync_option_names( array $names )`; a name ending in `*` is a prefix; names must start with `estasoft_sync_` and a bare prefix is refused) and every transient with the plugin prefix. An option that only shares the prefix is not touched. **Modules that store a new option must add its name through the filter** (the transient families of the Rest and Jobs modules are covered by the transient rule). User meta is shared by a whole network, so on multisite `erase()` leaves it alone by default and the uninstaller removes it once (`eraseUserMeta()`) only when every site chose to delete its data. Meta keys removed on uninstall come from `MetaKeys` (spec 5.10 plus every key the Woo and Jobs modules write, including `_estasoft_sync_stock_buffer`) and the filter `estasoft_sync_meta_keys( array $keys, string $kind )` (`order`, `product`, `user`); other modules must add the keys they write.

## Sync\PayloadResult

`new PayloadResult( array $payload = [], ?ConnectorError $error = null, ?int $mappingVersion = null, array $notes = [], array $sensitivePaths = [] )`. `$sensitivePaths` lists the payload paths that hold personal data (for example `partner.vat`); the queue hands them to the Logger so the request excerpt hides those fields even when their names look ordinary.
